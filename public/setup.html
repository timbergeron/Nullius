Set up Nullius

Configure one Discord application, deploy one Node service, and connect OpenRouter. Nullius answers only when its bot user is mentioned and does not store conversation text.

On this page Discord application VPS configuration OpenRouter and models Install in Discord Test the bot Troubleshooting

Step 1

Create the Discord application

  1. Open the Discord Developer Portal, choose New Application, and name it Nullius.
  2. Under General Information, copy the Application ID. This is DISCORD_CLIENT_ID.
  3. Under OAuth2 → General, reset and copy the Client Secret. This is DISCORD_CLIENT_SECRET.
  4. Add https://timbergeron.com/nullius/auth/discord/callback as an OAuth2 redirect and save it.
  5. Under Bot, reset and copy the bot token. This is DISCORD_BOT_TOKEN.
  6. Under Privileged Gateway Intents, enable Message Content Intent and save the change.
  7. Enable Requires OAuth2 Code Grant if Discord displays that option.
Keep secrets private. The client secret and bot token are passwords. Never paste them into chat, a web page, or Git.

You can set the bot avatar under Bot and the application icon under General Information. A square PNG or JPG of at least 512×512 works well.

Step 2

Configure the VPS

Nullius is deployed at /home/woods/codedev/Nullius and listens locally on port 3011.

ssh -i ~/.ssh/laq1.pem woods@la.quakeone.com
cd ~/codedev/Nullius
nano .env

Set the production values below. Generate APP_SECRET with openssl rand -hex 32.

PUBLIC_URL=https://timbergeron.com/nullius
PORT=3011
APP_SECRET=replace-with-a-generated-secret

DISCORD_CLIENT_ID=replace-with-application-id
DISCORD_CLIENT_SECRET=replace-with-client-secret
DISCORD_BOT_TOKEN=replace-with-bot-token

OPENROUTER_API_KEY=
OPENROUTER_MODEL=deepseek/deepseek-v4-flash

Protect the file, install dependencies, and verify the project:

chmod 600 .env
npm ci --omit=dev
npm run check
npm test

Install the prepared service and Nginx route:

sudo cp deploy/nullius.service /etc/systemd/system/nullius.service
sudo cp deploy/nginx-location.conf /etc/nginx/snippets/nullius.conf
sudo systemctl daemon-reload
sudo systemctl enable --now nullius
sudo nginx -t
sudo systemctl reload nginx
The HTTPS server block for timbergeron.com must include /etc/nginx/snippets/nullius.conf. See the repository README for the exact Nginx include.

Step 3

Connect OpenRouter and choose a model

Nullius needs an OpenRouter key before it can generate an answer. Choose either approach:

  • Operator-funded trial: set OPENROUTER_API_KEY in the VPS .env. Each installed server receives the configured number of trial answers.
  • Server-owned account: leave the operator key blank and have the server owner choose Connect OpenRouter on the Nullius setup page.

The model applies to every server. To use DeepSeek V4 Flash:

OPENROUTER_MODEL=deepseek/deepseek-v4-flash

After changing any environment value, restart Nullius:

sudo systemctl restart nullius

Step 4

Install Nullius in a server

  1. Open timbergeron.com/nullius.
  2. Choose Add to Discord, select the server, and approve the requested permissions.
  3. Return to the setup page. Optionally set a server nickname.
  4. If no operator trial key is configured, choose Connect OpenRouter and authorize a server-owned key.

Nullius requests only the channel access required to view messages, read reply history, send replies, send in threads, and change its own nickname.

Step 5

Test the bot

Choose Copy prompt & open Discord on the setup page, paste the prompt into a channel Nullius can access, and send it. You can also mention the bot manually:

@Nullius what can you help with?

To test conversation context, reply to an existing message and add:

@Nullius explain this in simple terms
Select the bot, not its role. Discord creates an automatic managed role named Nullius. In mention autocomplete, choose the entry marked APP or BOT with the bot avatar. A role mention looks similar but does not summon the current V1.

Troubleshooting

Nothing happens after a mention
Confirm you mentioned the APP/BOT user rather than the managed role. Also check that Nullius can view the channel, send messages, and read message history.
The service reports “Used disallowed intents”
Enable Message Content Intent under Discord Developer Portal → Bot → Privileged Gateway Intents, save, then restart the service.
Nullius says an admin must finish setup
Install it through the public setup page so the Discord server is recorded, then connect OpenRouter or configure the operator trial key.
Nullius cannot generate an answer
Confirm OpenRouter is connected, the account has credit, and OPENROUTER_MODEL contains a valid OpenRouter model ID.

Useful health and log commands:

curl https://timbergeron.com/nullius/healthz
sudo systemctl status nullius
sudo journalctl -u nullius -n 100 --no-pager

A healthy response is {"ok":true,"discord":true}.
