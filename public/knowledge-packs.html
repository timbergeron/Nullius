Knowledge-pack author guide

Teach Nullius a subject

A knowledge pack is a portable, declarative module that tells Nullius which evidence to index, when the subject applies, and how retrieval should be evaluated. Pack files contain no executable JavaScript.

On this page Requirements Create a pack Manifest reference Source types and mounts Activation Evaluations Build and install Reproduce QSS-M Security model

Before you start

Requirements

  • Nullius with Node.js 22.13 or newer.
  • Readable source material: a Git checkout, files stored in the pack, or a public HTTPS CSV.
  • Questions whose correct evidence you can identify. These become the retrieval evaluation set.

SQLite FTS5 is provided by Node through node:sqlite; the pack system adds no npm dependency. Generated indexes live under data/knowledge/ and are not committed.

Step 1

Create the pack directory

Choose a stable, lowercase, kebab-case ID. This example teaches Nullius about an imaginary Acme engine:

mkdir -p knowledge-packs/acme-engine
touch knowledge-packs/acme-engine/manifest.json
touch knowledge-packs/acme-engine/evaluations.json
touch knowledge-packs/acme-engine/README.md

The portable unit is the entire directory:

knowledge-packs/acme-engine/
├── manifest.json
├── evaluations.json
├── README.md
└── reference/              optional pack-owned files

Commit the directory, but do not commit data/knowledge/acme-engine.sqlite.

Step 2

Write manifest.json

This complete starter combines source code, documentation, history, and a catalog. Remove source objects you do not need.

{
  "schemaVersion": 1,
  "id": "acme-engine",
  "name": "Acme Engine Expert",
  "version": "1.0.0",
  "description": "Current Acme source, documentation, history, and settings.",
  "activation": {
    "mode": "auto",
    "keywords": ["acme engine", "acme-renderer"],
    "symbols": ["acmeinfo"],
    "stopSymbols": ["name", "status"]
  },
  "retrieval": {
    "maxResults": 8,
    "maxCharacters": 12000,
    "maxPerDocument": 2,
    "minScore": 0.2,
    "exactSymbolsFirst": true
  },
  "sources": [
    {
      "id": "engine",
      "type": "git-worktree",
      "label": "Acme source",
      "kind": "source",
      "authority": 1,
      "mount": "acme",
      "path": ".",
      "ref": "HEAD",
      "extractor": "c-source",
      "include": ["src/**/*.{c,h}"],
      "exclude": ["src/vendor/**"],
      "urlTemplate": "https://github.com/example/acme/blob/{revision}/{path}#L{startLine}"
    },
    {
      "id": "docs",
      "type": "files",
      "label": "Pack documentation",
      "kind": "doc",
      "authority": 0.8,
      "path": "reference",
      "extractor": "auto",
      "include": ["**/*.{md,html,txt}"],
      "exclude": []
    },
    {
      "id": "history",
      "type": "git-history",
      "label": "Acme history",
      "kind": "commit",
      "authority": 0.6,
      "mount": "acme",
      "path": ".",
      "ref": "HEAD",
      "maxCommits": 2000,
      "urlTemplate": "https://github.com/example/acme/commit/{revision}"
    }
  ],
  "answerPolicy": {
    "sourceOrder": ["engine", "docs", "history"],
    "mentionSymbolOrigin": false,
    "mentionDefaults": true
  },
  "evaluationsFile": "evaluations.json"
}

authority ranges from 0 to 1 and affects ranking. Give the evidence that describes current behavior the highest value. answerPolicy intentionally contains only validated source IDs and booleans; free-form prompt instructions are not allowed.

Step 3

Choose source types and configure mounts

git-worktree
Indexes tracked files from a local Git checkout. It records the branch and commit and supports include/exclude globs.
git-history
Indexes commit hashes, dates, subjects, bodies, and touched filenames from a validated Git ref.
files
Indexes an ordinary directory. A relative path without a mount must remain inside the pack directory.
csv
Indexes either a pack-owned CSV or a public HTTPS CSV. Catalog columns map possible header names to identifier, engine, category, type, description, and summary fields.

A pack names a mount such as acme; the operator chooses the real path through a predictable environment variable:

KNOWLEDGE_SOURCE_ACME=/srv/source/acme

Hyphens become underscores and names become uppercase: mount quake-tools maps to KNOWLEDGE_SOURCE_QUAKE_TOOLS. Packs cannot request arbitrary environment variables. The source’s path must resolve inside its mount, and symlinks cannot escape it.

Available file extractors are auto, c-source, markdown, html-doc, and text. C-family source is chunked by declaration/function and yields cvar, command, function, and filename symbols. Markdown and HTML are chunked by heading.

A remote catalog source looks like this:

{
  "id": "settings",
  "type": "csv",
  "label": "Settings catalog",
  "kind": "catalog",
  "authority": 0.75,
  "extractor": "command-catalog",
  "url": "https://example.com/public-settings.csv",
  "columns": {
    "identifier": ["Name", "Command / Variable"],
    "engine": ["Engine", "Version"],
    "category": ["Category"],
    "type": ["Type"],
    "description": ["Description"],
    "summary": ["Summary"]
  }
}

Step 4

Make activation specific

activation.mode: "auto" keeps a pack out of unrelated answers. Use:

  • keywords for unmistakable subject phrases such as a product or project name;
  • symbols only for known plain words that are unique enough to activate safely;
  • stopSymbols for indexed identifiers that are too ambiguous.

Identifier-shaped known symbols such as r_skywind, module.name, or +attack activate automatically. Ordinary words do not. Avoid broad keywords such as demo, record, music, or quake; they collide with normal conversation.

Use "mode": "always" only when every question in a selected server should use that subject.

Step 5

Write rank-aware evaluations first

Each positive question must activate the pack and find every expected item within the first three results by default. A rule may set maxRank explicitly. Fields on one rule must match the same result.

{
  "questions": [
    {
      "question": "Where is Acme fog rendered?",
      "expect": {
        "exactLocator": "src/render/fog.c",
        "kind": "source",
        "sourceId": "engine",
        "text": "Fog_Draw",
        "maxRank": 2
      },
      "forbid": {
        "locator": "src/vendor/",
        "maxRank": 3
      }
    },
    {
      "question": "What does acme_fog_density default to?",
      "expect": { "symbol": "acme_fog_density", "maxRank": 1 }
    }
  ],
  "offTopic": [
    "How dense is the fog tomorrow?",
    "Can you record a product demo?",
    "What music should I play?"
  ]
}

Expectation fields are exactLocator, partial locator, kind, sourceId, symbol, text, and maxRank. Use an array in expect when an answer needs separate evidence, such as source behavior plus catalog provenance. forbid rejects known bad results. Grow offTopic with realistic words that overlap your domain.

Step 6

Validate, build, test, and install

npm run knowledge:validate -- acme-engine
KNOWLEDGE_SOURCE_ACME=/srv/source/acme \
  npm run knowledge:build -- acme-engine
KNOWLEDGE_SOURCE_ACME=/srv/source/acme \
  npm run knowledge:test -- acme-engine
npm run knowledge:query -- acme-engine "what does acme_fog_density do?"

knowledge:validate reports only whether a required mount is set; it never prints its value. The build writes a uniquely named staging database and atomically replaces the previous index only after success.

Restart Nullius after adding a new pack or changing its manifest:

sudo systemctl restart nullius

After a source-only update, rebuild the same pack. A running Nullius process detects and safely reloads the replacement index automatically. If an index does not match its manifest version and hash, the pack stays unavailable until rebuilt.

Finally, visit the Nullius setup page as the Discord server owner and enable the ready pack under Knowledge.

When a pack supplies evidence for an answer, Nullius runs an adversarial second model pass over the first draft. That pass independently checks claims, citations, omissions, and unjustified certainty against the same evidence, then returns only the corrected answer. Requests that do not activate a pack remain single-pass. A pack-backed answer therefore normally incurs two model completions. The operator can set QSSM_OPENROUTER_MODEL to use a different server-controlled default for QSS-M and QSSM_PREMIUM_OPENROUTER_MODEL to upgrade the final review automatically. QSSM_PREMIUM_DAILY_LIMIT defaults to one successful premium review per server each UTC day; zero disables it. Failed premium reviews do not consume the quota, and Nullius stores only the UTC date and count. Model choice never comes from the pack itself.

Worked example

Reproduce the QSS-M module

The checked-in knowledge-packs/qssm directory is a complete example. From a fresh machine:

git clone https://github.com/timbergeron/Nullius.git
git clone https://github.com/timbergeron/QSS-M.git
cd Nullius
npm ci

export KNOWLEDGE_SOURCE_QSSM="$(cd ../QSS-M && pwd)"
npm run knowledge:validate -- qssm
npm run knowledge:build -- qssm
npm run knowledge:test -- qssm
npm run knowledge:query -- qssm "where is the skybox rendering code?"

The pack indexes current QSS-M engine source, selected project documentation, 3,000 commits, and the public commands-and-variables Google Sheet. Vendored image/JSON libraries are excluded because they add vocabulary without describing QSS-M behavior.

To reproduce the same source snapshot later, record the output of:

git -C ../QSS-M rev-parse HEAD

Then check out that commit before rebuilding. The public sheet is intentionally live; for byte-for-byte historical reproduction, export it to a CSV inside the pack and change the source from url to a contained path.

Reference

Security and resource limits

  • Pack-relative files and mounted files are realpath-contained; traversal and symlink escapes fail.
  • Remote CSV requests require public HTTPS on port 443. Every redirect is revalidated, private/loopback destinations are blocked, and downloads stream through an 8 MiB byte limit.
  • File count, per-file size, total source size, commit count, result count, and prompt characters are bounded.
  • Git runs through argument-safe process execution and refs that resemble options are rejected.
  • Evidence is JSON encoded, delimiter characters are escaped, and the model is told that all reference text is untrusted data.
  • Free-form pack prompt instructions are not supported. Use only the validated answerPolicy fields.
Review packs before installing them. A pack cannot execute code through the pack system, but it chooses which files inside an explicitly configured source mount are indexed and which public CSV endpoint is contacted.
